## 二、问题清单（⚠️ 待排查）

### 问题 #1（已修复 ✅ · 前端）~~前端保存笔记时未同步 cites 到 frontmatter~~

- **状态**：2026-08-19 已修复（前端三处改动，待用户实际验证）。
- **现象**：笔记正文含 `[[cite:文献ID]]`（F5 划词转笔记写入 / F6 引用徽章），但 frontmatter 的 `cites` 字段不更新。
- **影响**：
  1. B8 导出（`/api/export/references`、`/api/export/bibtex`）聚合的是 **frontmatter cites** → 真实笔记导出为空（本次联调实测 references/bibtex 均空）；
  2. 文献详情"反向引用"（F4 扫 `notes[].cites`）不完整。
- **证据**：当前 vault 两篇笔记 frontmatter 均无 cites（`title/collection/tags` only）；手工写入带 `cites: [文献ID]` 的笔记后，references/bibtex 导出完全正常 → **后端聚合逻辑没问题，缺口在前端**。
- **根因（前端）**：编辑器自动保存只更新 `content`（Markdown），`Note.cites` 来自 loadAll 时的文件解析；F6 引用节点插入/编辑后，没有任何逻辑把文档中的 cite 节点 ID 集合写回 `Note.cites` → serializeNote 落盘时 cites 恒为空/旧值。
- **修复内容（前端三处）**：
  1. `src/lib/citation.ts` + `collectCiteIds(doc)`：遍历 ProseMirror doc 收集 cite 节点 id（去重保序、过滤空），与 CitationList 扫描同源；
  2. `src/pages/editor/index.tsx`（`debouncedSaveCurrentNote`）：保存时 `collectCiteIds(editor.state.doc)` → 写入 `note.cites`（全量扫描，删除引用后自动为空 → frontmatter 移除 cites）；
  3. `src/components/Reader/cite-picker.tsx`（`handleConfirm`）：划词转笔记新建传 `cites: [文献id]`、追加传 `cites: 旧值合并去重`。
- **验证**：tsc ✅ / vite build ✅ / collectCiteIds 单测 ✅（去重保序过滤空）。待浏览器实际验证：编辑器保存后文件 frontmatter 含 cites、B8 导出有条目。

### 问题 #2（低优先级 · 可自愈）：导入/删除文献后 index_state.json 未同步

- **现象**：
  - 导入新文献后：`/api/kb/status` 的 `unindexedFiles` 误报该文献"未索引"（实际 Chroma 已建索引，导入时 upsert 过）；
  - 删除文献后：`indexedPapers` / `chunks` 虚高（state 残留旧记录）。
- **证据**：删除文献后 `indexedPapers=1, chunks=199`（预期 0）；恢复导入后 `unindexed=['文献/0c35146d59c6_PGFD-YOLO.pdf']`。
- **自愈路径**：跑一次 `POST /api/kb/refresh`（增量）即修正（本次实测 `deleted=1, indexed=1`，之后 status 一致）；重启后端自动 scan 同样自愈。
- **根因**：`documents.py` 导入/删除只操作 Chroma + literature.json，**不更新 `.kb/index_state.json`**（B6 的 state 由 scan_and_index 维护）→ status 统计与实际索引脱节。
- **影响**：仅状态显示不准确（前端 30s 轮询 status 会短暂看到误报）；真实检索不受影响。
- **修复方向**：documents.py 导入成功后、删除时同步增删 index_state.json 记录（或在 status 计算时以 literature.json 为权威源）。

## 三、观察项（🔍 非阻断，可选优化）

1. **普通对话也强制附来源**：chat system prompt 要求"注明来源"，问"1+1=？"也返回"2（来源：新笔记-我的笔记）"。可选优化：`build_rag_context` 返回空/低相关时提示模型"检索内容与问题无关可忽略"。
2. **单篇检索 top-5 未命中目标 chunk**：query "PGFD-YOLO 论文中 LKC3-F 模块的作用" 的 top-5 命中的是实验结果/相关工作页，**不含** LKC3-F 描述（第 3/6 页）。embedding 检索相关性问题，可评估 top_k 或分块粒度。
3. **Chroma 删除后立即查询偶发异常**：删除文献后立即 `retrieve` 报 chromadb 内部查询异常（B6 模块说明已记录同类偶发：chromadb 1.5.9 + langchain-chroma 0.2.6 删除后立即检索报错，0/8 复现）。本次复现 1 次。建议固定 chromadb 版本或升级 langchain-chroma 观察。
