# 后端接口文档（前后端对接合同）

> 版本：v1（2026-08-14）｜ 对应分支：backend ｜ 前端 F1 起以本文为准对接
> 后端已实现接口：`/api/fs/*`（B4）、`/api/chat`（基线）、`/health`、`/ping`
> 规划中接口（B5-B8 实现，见文末预告）：`/api/documents`、`/api/kb/*`、`/api/export/*`

## 1. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | `http://localhost:3001`（后端 dev：`uvicorn app.main:app --port 3001`） |
| CORS | 已全开（`allow_origins=["*"]`），浏览器直连无跨域问题 |
| 编码 | 请求/响应一律 UTF-8；路径参数需 URL 编码（`encodeURIComponent`） |
| 路径语义 | **所有 `path` 都是 vault 内相对路径**（如 `笔记/xx.md`），空串 = vault 根 |
| 错误格式 | 普通 API：HTTP 状态码 + `{"detail": "原因"}`；`/api/chat`：HTTP 200 + SSE `error` 事件（见 2.4） |
| 目录穿越 | 越界路径一律 403，前端无需防御，但也不应构造 |

## 2. 已实现接口

### 2.1 文件 API（`/api/fs/*`，B4）

#### GET `/api/fs/list` — 列目录

```
请求：/api/fs/list?path=笔记
响应 200：{"entries": [{"name": "xx.md", "isDir": false, "path": "笔记/xx.md"}, ...]}
```
- 排序：目录在前、文件在后，名称小写字典序
- `path` 字段为相对 vault 路径，可直接作为其他接口参数
- 错误：404 目录不存在 / 400 不是目录 / 403 越界

#### GET `/api/fs/read` — 读文本（utf-8）

```
请求：/api/fs/read?path=笔记/xx.md
响应 200：{"content": "# 标题\n正文..."}
```
- 错误：404 不存在 / 400 不是文件或二进制无法按文本读 / 403 越界

#### GET `/api/fs/file` — 二进制文件流（PDF 等）

```
请求：/api/fs/file?path=文献/2401.xxxxx.pdf
响应 200：PDF 二进制（Content-Type: application/pdf）
```
- 前端 `fetch(url)` 后 `res.blob()` 即可，pdf.js 直接用
- 错误：404 / 400 / 403

#### POST `/api/fs/write` — 写文件（创建/覆盖一体）

```
请求：POST /api/fs/write?path=笔记/xx.md
body：{"content": "要写的内容"}（JSON）
响应 200：{"ok": true}
```
- **自动创建父目录**（`笔记/新建/xx.md` 无需先 mkdir）
- 服务端原子写（tmp + os.replace），前端可放心高频调用
- 错误：400 目标是目录 / 422 body 非 JSON / 500 写入失败 / 403 越界

#### POST `/api/fs/mkdir` — 建目录（支持多级）

```
请求：POST /api/fs/mkdir?path=笔记/子目录
响应 200：{"ok": true}
```
- 错误：400 已存在 / 403 越界

#### DELETE `/api/fs/delete` — 删除文件或空目录

```
请求：DELETE /api/fs/delete?path=笔记/xx.md
响应 200：{"ok": true}
```
- 目录非空拒绝（400），**无递归删除**——前端如需删树需逐个删
- 错误：404 不存在 / 400 非空 / 403 越界

#### GET `/api/fs/exists` — 存在性检查

```
请求：/api/fs/exists?path=笔记/xx.md
响应 200：{"exists": true}
```
- 注意：不存在的路径返回 200 + `{"exists": false}`（非 404）

#### 前端 fetch 参考（HttpFsAdapter 直接可用）

```ts
// 列目录
const res = await fetch(`http://localhost:3001/api/fs/list?path=${encodeURIComponent(path)}`)
const { entries } = await res.json()

// 读文本
const res = await fetch(`http://localhost:3001/api/fs/read?path=${encodeURIComponent(path)}`)
const { content } = await res.json()

// 写文件
const res = await fetch(`http://localhost:3001/api/fs/write?path=${encodeURIComponent(path)}`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ content }),
})

// 下载 PDF（blob）
const res = await fetch(`http://localhost:3001/api/fs/file?path=${encodeURIComponent(path)}`)
const blob = await res.blob()
```

### 2.2 文献管理 API（`/api/documents/*`，B5）

#### POST `/api/documents` — 导入 PDF

```
请求：multipart/form-data
  file     （必填）PDF 文件
  doi      （可选）DOI，自动补全元数据
  arxivId  （可选）arXiv ID，自动补全元数据
响应 201：{完整 LiteratureEntry}
```
- 保存为 `vault/文献/{id}_{清洗后原文件名}.pdf`（id 为 12 位 hex）
- 补全失败：title 用文件名占位，照常入库（前端可后续编辑）
- 重复导入（同 DOI / arXiv ID）→ 409 `{"detail": "文献已存在（标题）"}`
- 错误：400 非 PDF 或超 50MB / 409 重复 / 403 越界（不应发生）

**LiteratureEntry 字段**：
```
id, title, authors[{given,family}], year, venue, volume, issue, pages,
doi, arxivId, pdfPath(vault 相对路径), status("未读"), collectionIds[], tags[], importedAt
```

前端 fetch 参考：
```ts
const form = new FormData()
form.append('file', pdfBlob, 'paper.pdf')
if (arxivId) form.append('arxivId', arxivId)
const res = await fetch('http://localhost:3001/api/documents', { method: 'POST', body: form })
const entry = await res.json()
```

#### GET `/api/documents` — 文献列表

```
响应 200：{"entries": [LiteratureEntry...]}（importedAt 倒序）
```

#### DELETE `/api/documents/{id}` — 删除文献

```
响应 200：{"ok": true} ｜ 404：不存在
```
- 同步清理：PDF 文件 + 向量索引 + literature.json

|---|---|---|

| GET | `/health` | `{"status": "ok"}`（前端可用它判断后端是否在线） |

### 2.3 AI 问答（`POST /api/chat`，基线协议，前端 services/ai.ts 已有实现）

请求体（二选一）：

```
A. 对话模式：{"messages": [{"role": "user", "content": "..."}], "noteContext": "当前笔记内容"}
B. 任务模式：{"taskType": "summarize|polish|continue", "text": "要处理的文本"}
```

响应：`text/event-stream`（SSE），事件格式：
```
data: {"content": "增量文本"}
data: {"error": "错误信息"}   ← 出错时
```
- **错误约定：一律 HTTP 200 + SSE error 事件**，前端按 `data.error` 分支处理
- `noteContext` 可选，传了会注入 system prompt（B7 将在此协议上加 RAG 检索注入，格式不变）

## 4. 状态码速查

| 状态码 | 含义 | 常见触发 |
|---|---|---|
| 200 | 成功（含 exists=false） | — |
| 400 | 参数/类型不匹配、目录非空 | read 二进制、写目录、删非空目录 |
| 403 | **路径越界**（目录穿越防护） | 传 `../` 等 |
| 404 | 路径不存在 | 读不存在的文件 |
| 405 | 方法不允许 | 用 GET 打 DELETE 路由 |
| 422 | body 校验失败 | write 的 body 不是 `{"content": ...}` |
| 500 | 服务端写入失败 | 磁盘问题 |
